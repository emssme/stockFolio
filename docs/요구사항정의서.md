# StockFolio 요구사항정의서

**문서 버전:** 1.0  
**작성일:** 2026-04-11  
**프로젝트명:** StockFolio — 실시간 주식/코인 포트폴리오 트래커

---

## 1. 프로젝트 개요

### 1.1 목적
사용자가 보유 중인 주식 및 암호화폐 자산을 한 곳에서 등록·관리하고, 실시간 시세를 반영한 수익률과 포트폴리오 현황을 시각적으로 확인할 수 있는 웹 서비스를 제공한다.

### 1.2 범위
- 회원 인증 및 계정 관리
- 포트폴리오(자산) 등록·수정·삭제
- 실시간 시세 연동 및 수익률 계산
- 수익률 차트 시각화
- Redis 캐싱을 통한 성능 최적화

### 1.3 기술 스택

| 구분 | 기술 |
|------|------|
| Backend | Spring Boot, Spring Security, JPA |
| Frontend | React |
| Database | MySQL 8.0, Redis |
| 실시간 통신 | WebSocket |
| 배포 | GCP (Google Cloud Platform) |
| 개발 언어 | Java 17 |

## 3. 기능 요구사항

### 3.1 회원 인증 (AUTH)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| AUTH-01 | 이메일 + 비밀번호로 회원가입이 가능해야 한다 | 필수 |
| AUTH-02 | 회원가입 시 이메일 중복 검사를 수행해야 한다 | 필수 |
| AUTH-03 | 비밀번호는 bcrypt로 암호화하여 저장해야 한다 | 필수 |
| AUTH-04 | 이메일 + 비밀번호로 로그인 시 JWT Access Token과 Refresh Token을 발급해야 한다 | 필수 |
| AUTH-05 | Access Token 만료 시 Refresh Token으로 재발급이 가능해야 한다 | 필수 |
| AUTH-06 | 로그아웃 시 Refresh Token을 무효화해야 한다 | 필수 |
| AUTH-07 | 인증되지 않은 요청에 대해 401 응답을 반환해야 한다 | 필수 |

### 3.2 사용자 계정 관리 (USER)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| USER-01 | 로그인한 사용자는 자신의 프로필(닉네임, 이메일)을 조회할 수 있어야 한다 | 필수 |
| USER-02 | 사용자는 닉네임을 수정할 수 있어야 한다 | 선택 |
| USER-03 | 사용자는 비밀번호를 변경할 수 있어야 한다 | 선택 |
| USER-04 | 사용자는 계정을 탈퇴(소프트 삭제)할 수 있어야 한다 | 선택 |

### 3.3 포트폴리오 자산 관리 (PORTFOLIO)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| PF-01 | 사용자는 자산(종목코드, 종목명, 수량, 매입가)을 등록할 수 있어야 한다 | 필수 |
| PF-02 | 등록 가능한 자산 유형은 국내 주식, 해외 주식, 암호화폐를 포함해야 한다 | 필수 |
| PF-03 | 사용자는 등록한 자산의 수량과 매입가를 수정할 수 있어야 한다 | 필수 |
| PF-04 | 사용자는 등록한 자산을 삭제할 수 있어야 한다 | 필수 |
| PF-05 | 사용자는 자신의 전체 자산 목록을 조회할 수 있어야 한다 | 필수 |
| PF-06 | 각 자산별 현재 평가금액, 수익금액, 수익률(%)이 표시되어야 한다 | 필수 |
| PF-07 | 포트폴리오 전체의 총 매입금액, 총 평가금액, 총 수익률이 집계되어야 한다 | 필수 |
| PF-08 | 동일 종목을 여러 번 나눠 매입한 경우 평균 매입가로 합산 관리가 가능해야 한다 | 선택 |

### 3.4 실시간 시세 연동 (QUOTE)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| QT-01 | 서버는 외부 시세 API로부터 주식 및 코인 현재가를 주기적으로 수신해야 한다 | 필수 |
| QT-02 | 클라이언트는 WebSocket을 통해 실시간 시세 업데이트를 수신해야 한다 | 필수 |
| QT-03 | WebSocket 연결이 끊겼을 때 클라이언트는 자동으로 재연결을 시도해야 한다 | 필수 |
| QT-04 | 시세 데이터는 Redis에 캐싱되어 외부 API 호출을 최소화해야 한다 | 필수 |
| QT-05 | 시장이 마감된 경우 마지막 종가를 표시해야 한다 | 필수 |

### 3.5 수익률 차트 시각화 (CHART)

| ID | 요구사항 | 우선순위 |
|----|----------|----------|
| CH-01 | 포트폴리오 전체 수익률의 시간별 변화 추이를 선 그래프로 표시해야 한다 | 필수 |
| CH-02 | 자산별 비중을 파이(도넛) 차트로 시각화해야 한다 | 필수 |
| CH-03 | 차트 조회 기간을 1일, 1주, 1개월, 3개월, 1년으로 선택할 수 있어야 한다 | 선택 |
| CH-04 | 차트 데이터는 포트폴리오 스냅샷을 주기적으로 저장하여 이력 기반으로 제공해야 한다 | 선택 |

## 4. 비기능 요구사항

### 4.1 성능

| ID | 요구사항 |
|----|----------|
| PERF-01 | 일반 API 응답 시간은 95% 이상의 요청에서 500ms 이내여야 한다 |
| PERF-02 | 시세 캐시 TTL은 10초로 설정하여 실시간성과 API 부하 사이의 균형을 맞춘다 |
| PERF-03 | WebSocket으로 시세 업데이트는 최대 5초 이내에 클라이언트에 전달되어야 한다 |

### 4.2 보안

| ID | 요구사항 |
|----|----------|
| SEC-01 | 모든 API 통신은 HTTPS를 사용해야 한다 |
| SEC-02 | JWT Access Token 유효기간은 30분, Refresh Token은 7일로 설정한다 |
| SEC-03 | 사용자는 자신의 포트폴리오 데이터만 접근할 수 있어야 한다 (타 사용자 데이터 접근 불가) |
| SEC-04 | SQL Injection, XSS 등 OWASP Top 10 취약점에 대한 방어 처리가 되어야 한다 |

### 4.3 가용성 및 배포

| ID | 요구사항 |
|----|----------|
| AVAIL-01 | GCP에 배포하며 서비스 가용성 99% 이상을 목표로 한다 |
| AVAIL-02 | 서버 배포 시 무중단 배포(롤링 또는 블루/그린)를 지원해야 한다 |

## 5. 데이터 모델 (논리 설계)

### 5.1 주요 엔티티

```
User
├── id (PK)
├── email (unique)
├── password (encrypted)
├── nickname
├── createdAt
└── deletedAt (소프트 삭제)

Asset (포트폴리오 자산)
├── id (PK)
├── userId (FK → User)
├── assetType (STOCK_KR / STOCK_US / CRYPTO)
├── ticker (종목 코드)
├── name (종목명)
├── quantity (수량)
├── avgPurchasePrice (평균 매입가)
└── createdAt / updatedAt

QuoteCache (Redis)
├── key: "quote:{ticker}"
├── currentPrice
└── ttl: 10s

PortfolioSnapshot (선택 — 차트 이력용)
├── id (PK)
├── userId (FK → User)
├── totalValue (총 평가금액)
├── totalProfit (총 수익금액)
└── snapshotAt
```

## 6. API 설계 (개요)

| Method | Endpoint | 설명 | 인증 |
|--------|----------|------|------|
| POST | /api/auth/signup | 회원가입 | 불필요 |

## 8. 제약 사항

- 외부 시세 API는 무료 플랜 사용 시 분당 호출 횟수 제한이 있으므로 Redis 캐싱이 필수이다.
- 암호화폐 시세는 24시간 제공되나 국내 주식은 장 운영 시간(09:00~15:30 KST)에만 실시간 시세가 제공된다.
- MVP 범위에서 소셜 로그인(OAuth)은 제외하고 이메일 인증만 지원한다.

## 9. 외부 API 연동

| 자산 유형 | 서비스 | 비고 |
|-----------|--------|------|
| 국내 주식 (STOCK_KR) | 한국투자증권 Open API | REST + WebSocket, 무료, 개인 계좌 필요 |
| 해외 주식 (STOCK_US) | Finnhub | REST, 무료 플랜 60 req/min |
| 암호화폐 (CRYPTO) | Binance WebSocket | WebSocket, 무료, 실시간 스트리밍 |

## 10. 용어 정의

| 용어 | 정의 |
|------|------|
| 매입가 | 사용자가 자산을 구매한 단가 |
| 평균 매입가 | 동일 종목을 여러 번 매입했을 때의 가중평균 단가 |
| 평가금액 | 현재 시세 × 보유 수량 |
| 수익금액 | 평가금액 − (평균 매입가 × 보유 수량) |
| 수익률 | 수익금액 / (평균 매입가 × 보유 수량) × 100 (%) |
| 스냅샷 | 특정 시점의 포트폴리오 총 평가금액 기록 |
